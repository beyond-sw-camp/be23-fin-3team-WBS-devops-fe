# 반품 출고 시나리오 (Return Outbound)

> **정의**: 우리가 입고처(공급사)로부터 받은 상품에 문제가 있어 다시 입고처로 보내는 흐름.
> **도메인**: B2B WMS — 사전 통보 + 원본 입고지시서 매칭형.

---

## 트리거

다음 중 하나로 불량/오배송 발견:

1. **입고 검수 단계에서 발견** — `defective_qty` 잡힘
2. **보관 중 발견** — 적치 후 시간이 지나 발견된 결함
3. **출고 시점에 발견** — 피킹·검수 단계에서 발견 후 출고 보류

영업/CS팀이 입고처 X에 클레임 → 반품 동의·회수 일정 협의.

---

## 단계별 흐름

### T0. 입고처 협의 (시스템 외부)

- 우리 → 입고처 X: 클레임 통보
- 입고처: 반품 동의, 회수 방법 결정 (택배 회수 / 직접 수거)
- **WMS 책임 X** — 영업/CS 영역

### T1. 시스템 등록 — [반품 출고 접수]

운영자가 반품 출고 접수 화면에 진입:

| 입력 항목 | 설명 |
|---|---|
| 원본 입고지시서 (필수) | IB-XXXX 검색·선택 — 매칭의 핵심 |
| 반품 품목·수량 | 입고건의 received_qty 이내에서 선택 |
| 출고 창고 | 그 입고가 들어간 창고 (자동 추천) |
| 사유 | 입고불량 / 잘못받음 / 사양불일치 / 기타 |
| 회수 방법 (옵션) | 택배 발송 / 입고처 회수 |

→ 시스템이 **반품 출고 지시서**를 생성:
- `source = 'return'`
- `return_from = 'IB-XXXX'`
- 출고처: 입고처 X (방향 반대 — 일반 출고는 매장이지만 반품은 공급사)
- 그 외 필드는 일반 출고지시서와 동일

### T2. 피킹

- 일반 피킹 리스트 흐름 사용
- 불량품 보관 위치 또는 일반 위치에서 해당 수량 피킹
- 피킹 작업자에게 "반품 출고" 라벨 표시 (일반 출고와 구분)

### T3. 출고 (발송)

- 입고처 X 주소로 발송 (택배) 또는 입고처 회수업체에 인계
- 출고 전표 발행 (반품 사유 명시)

### T4. 재고 차감

- 발송된 수량만큼 재고 -N
- 양품이었으면 available -N
- 불량 보관 재고였으면 defective -N

### T5. 회계 연동 (시스템 외부)

- ERP에 매입처 클레임 데이터 전송
- 매입대금 차감 또는 환불 처리
- **WMS 책임 X**

| 단계 | WMS | 외부 시스템 |
|---|---|---|
| T0 협의 | - | CRM/메일 |
| **T1 등록** | ✅ | - |

| T5 정산 | - | ERP |

## 데이터 모델

### 출고 지시서 (Outbound Order) — 반품 출고도 같은 테이블 사용

추가/구분 필드:
- `source: 'sales_order' | 'manual' | 'return'`
- `return_from: string | null` — 원본 입고지시서 번호 (IB-XXXX)
- `return_reason: '입고불량' | '잘못받음' | '사양불일치' | '기타' | null`
- `destination_type: 'store' | 'supplier'` — 일반 출고는 'store', 반품 출고는 'supplier'
- `supplier_id: string | null` — 반품 대상 입고처 (일반 출고는 store_id 사용)

### 변경 사항

원본 입고지시서:
- 그대로 유지 (반품으로 변경되지 않음)
- 반품된 수량을 별도로 추적 (`returned_to_supplier_qty` 컬럼 또는 조회 시 집계)

## 화면 흐름

```
[반품 관리] 메뉴
  └─ 반품 출고 접수 (신규 페이지 — 3-step Wizard)
       1. 원본 입고지시서 검색·선택
       2. 반품 품목·수량 입력
       3. 사유·회수 방법 등 부가정보 → 제출
                ↓
       반품 출고 지시서 생성 → 일반 출고 흐름 진입
                ↓
[출고 관리] 메뉴 또는 [반품 관리 > 반품 출고 목록]
  ├─ 피킹 리스트
  ├─ 출고 확정
  └─ 출고 전표
```

## 백엔드 필요 작업

### 신규 API

```
POST /stock-service/outbound/return
Body: {
  "inboundOrderId": "uuid",         // 원본 입고지시서
  "warehouseId": "uuid",             // 출고 창고
  "supplierId": "uuid",              // 반품 대상 입고처
  "reason": "입고불량",
  "returnMethod": "courier" | "pickup",
  "items": [
    { "productId": "uuid", "qty": 10 }
  ]
}
→ OutboundOrder (source='return', return_from=IB-XXXX)
```

### 기존 API 확장 (옵션)

- 출고 지시서 목록 GET/search에 `source` 필터 파라미터 추가
- 반품 출고 목록 화면에서 `source='return'`으로 좁히기 위함

---

## 일반 출고와의 차이 (요약)

| 항목 | 일반 출고 | 반품 출고 |
|---|---|---|
| 진입 | 수주서 / 수동 생성 | 입고지시서 매칭 |
| 도착처 | 매장(store) | 입고처(supplier) |
| 사유 필드 | 없음 | 필수 |
| 피킹 위치 | 양품 위치 | 양품 + 불량 위치 |
| 재고 차감 | available -N | available 또는 defective -N |
| 회계 | 매출 발생 | 매입대금 차감 |

---

## 향후 작업

1. 사이드바에 "반품 관리" 그룹 신설
2. **반품 출고 접수 페이지 신규 작성** (ReturnInboundPage 패턴 미러링)
   - Step 1: 입고지시서 검색·선택 (`searchInboundOrders` 재사용)
   - Step 2: 반품 품목·수량 입력
   - Step 3: 사유·회수 방법 → 제출 → 새 BE API 호출
3. **BE에 반품 출고 생성 API 요청** (위 스펙)
4. 반품 출고 목록 화면 신설 (출고지시서에서 source='return' 필터)
5. 일반 출고지시서 목록에서 source='return' 자동 제외 옵션
