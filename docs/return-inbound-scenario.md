# 반품 입고 시나리오 (Return Inbound)

> **정의**: 우리가 거래처(매장/고객사)에 출고했던 상품을 거래처가 다시 우리에게 보내는 흐름.
> **도메인**: B2B WMS — 사전 통보 + 원본 출고지시서 매칭형.

---

## 트리거

거래처가 "주문번호 OB-XXXX 중 N개 반품"을 메일·전화·EDI 등으로 통보.
영업/CS팀이 RMA(Return Merchandise Authorization)에 동의.

---

## 단계별 흐름

### T0. 거래처 통보 (시스템 외부)

- 거래처 → 우리: 반품 의사 전달
- 우리 영업/CS팀: RMA 동의, 회수 일정 협의
- **WMS 책임 X** — 메일/CRM 영역

### T1. 거래처가 상품 발송

- 거래처가 택배·직배송으로 우리 창고로 발송
- 송장에 "OB-XXXX 반품" 표기 (또는 RMA 번호)

### T2. 박스 도착

- 운영자가 창고에서 박스 수령
- 송장 정보로 어느 출고건의 반품인지 식별

### T3. 시스템 등록 — [반품 입고 접수]

운영자가 반품 입고 접수 화면에 진입:

| 입력 항목 | 설명 |
|---|---|
| 원본 출고지시서 (필수) | OB-XXXX 검색·선택 — 매칭의 핵심 |
| 반품 품목·수량 | 출고건의 picked_qty 이내에서 선택 |
| 입고할 창고 | 어느 창고로 들일지 |
| 사유 | 불량 / 단순변심 / 오배송 / 기타 |

→ 시스템이 **반품 입고 지시서**를 생성:
- `source = 'return'`
- `return_from = 'OB-XXXX'`
- 그 외 필드는 일반 입고지시서와 동일

### T4. 검수

- 운영자가 박스 열어 실물 확인
- 일반 입고와 동일한 receive 단계 사용
- 양품 / 불량 / 폐기 분류
  - `received_qty`: 양품
  - `defective_qty`: 불량

### T5. 적치

- 양품 → 일반 재고 위치 (적치 추천 활용)
- 불량 → 불량품 보관 위치 또는 폐기 큐
- 일반 적치 흐름과 동일

### T6. 재고 환원

- 양품 수량만큼 available 재고 +N
- 불량은 별도 상태로 보관 → **시나리오 ② (반품 출고)**로 이어질 수 있음

### T7. 회계 연동 (시스템 외부)

- ERP에 반품 알림 → 환불·매출 차감 처리
- **WMS 책임 X**

## WMS 책임 범위

| 단계 | WMS | 외부 시스템 |
|---|---|---|
| T0 통보 | - | CRM/메일 |
| T1~T2 도착 | - | - (물리) |
| **T3 등록** | ✅ | - |
| **T4 검수** | ✅ | - |
| **T5 적치** | ✅ | - |
| **T6 재고 환원** | ✅ | - |
| T7 정산 | - | ERP |

---

## 데이터 모델

### 입고 지시서 (Inbound Order) — 반품 입고도 같은 테이블 사용

추가/구분 필드:
- `source: 'purchase_order' | 'manual' | 'return'`
- `return_from: string | null` — 원본 출고지시서 번호 (OB-XXXX)
- `return_reason: '불량' | '단순변심' | '오배송' | '기타' | null`

### 변경 사항

원본 출고지시서:
- 그대로 유지 (반품으로 변경되지 않음)
- 반품된 수량을 별도로 추적 (`returned_qty` 컬럼 또는 조회 시 집계)

## 화면 흐름

```
[반품 관리] 메뉴
  └─ 반품 입고 접수 (ReturnInboundPage — 3-step Wizard)
       1. 원본 출고지시서 검색·선택
       2. 반품 품목·수량 입력
       3. 창고·사유 등 부가정보 → 제출
                ↓
       반품 입고 지시서 생성 → 일반 입고 흐름 진입
                ↓
[입고 관리] 메뉴 또는 [반품 관리 > 반품 입고 목록]
  ├─ 검수 (입고 지시서 상세)
  ├─ 적치 (적치 지시서)
  └─ 입고 전표
```

---

## 권한

- 반품 입고 접수: `INBOUND CREATE`
- 검수·적치: 일반 입고와 동일

---

## 현재 구현 상태

| 항목 | 상태 |
|---|---|
| 반품 입고 접수 화면 | ✅ ReturnInboundPage |
| 출고지시서 검색 | ✅ 클라이언트 필터 |
| 반품 입고 지시서 생성 API | ✅ `useCreateFromReturn` 훅 |
| 입고 지시서 목록에서 반품 표시 | ✅ source='return' 태그 |
| 입고 지시서 상세에서 반품 표시 | ✅ "반품 입고" 알림 + return_from |
| **반품 관리 메뉴 그룹 분리** | ❌ 현재 "입고 관리" 안에 있음 — 분리 예정 |
| **반품 입고 목록 (필터 뷰)** | ❌ 입고지시서 목록에 섞여 있음 — 분리 예정 |

## 향후 작업 (B2B 결정 + 메뉴 분리 결정)

1. 사이드바에 "반품 관리" 그룹 신설
2. ReturnInboundPage를 그룹 안으로 이동
3. "반품 입고 목록" 화면 신설 (입고지시서에서 source='return' 필터)
4. 일반 입고지시서 목록에서 source='return' 자동 제외 옵션
