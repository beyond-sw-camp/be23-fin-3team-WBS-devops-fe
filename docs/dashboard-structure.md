# 대시보드 화면 구성 안내

이 문서는 우리 WMS 대시보드 화면이 **왜 이렇게 생겼는지**, **어떤 흐름으로 정보를 보여주는지** 설명하는 글입니다. 신규 인원이 들어오거나, 새로운 패널을 추가할 때 참고하세요.

---

## 1. 대시보드가 보여주려는 것

한 마디로 이거예요.

> **"지금 내가 뭘 해야 하지?"** 를 화면 켜자마자 알 수 있게 해주는 곳.

창고 일은 "오늘 들어올 입고", "오늘 나갈 출고", "결재해야 할 지시서", "재고 부족한 물품" 이런 게 매일 쌓여요. 이걸 메뉴 하나하나 들어가서 확인하면 시간이 너무 걸립니다. 그래서 대시보드는 **이 모든 걸 한 화면에 모아서** 보여주는 역할을 해요.

---

## 2. 화면이 어떻게 생겼나

대시보드는 위에서 아래로 **세 단계로** 정보를 풀어줍니다.

```
┌─────────────────────────────────────────────────────┐
│   ① 큰 숫자 5개 (KPI 카드)                          │  ← 한눈에 상황 파악
├─────────────────────────────────────────────────────┤
│   ② 처리 필요 지시서 / 오늘 처리 현황 / 창고 미니맵  │  ← 무엇을 / 어디까지 / 어디서
├─────────────────────────────────────────────────────┤
│   ③ 7일 추이 / 오늘의 이슈 / 재고 부족 품목         │  ← 흐름과 경보
├─────────────────────────────────────────────────────┤
│   ④ 최근 작업 로그                                   │  ← 누가 뭘 했나
└─────────────────────────────────────────────────────┘
```

위쪽 = 가장 압축된 정보. 아래쪽으로 갈수록 자세해집니다.

---

## 3. 같은 정보를 세 번 다르게 보여주는 이유

대시보드의 핵심 아이디어는 이거예요.

> **"같은 사실을 세 가지 형태로 보여주면, 사용자는 자연스럽게 행동까지 이어진다."**

예를 들어 **출고 지시서가 3건 미처리** 라는 사실이 있으면 화면에 이렇게 나옵니다:

**① 큰 숫자 (KPI 카드)**
> "오늘 출고 **3건**"
>
> 그냥 숫자만 봐요. "아, 3건 있구나" 인지.

**② 행동 가능한 리스트 (처리 필요 지시서)**
> ```
> [지연]   OB-2026-001  롯데하이마트  품목 2종, 수량 120
> [오늘]   OB-2026-002  GS25         품목 1종, 수량 50
> [진행중] OB-2026-003  CU            품목 3종, 수량 80
> ```
> 이번엔 **무엇 무엇인지** 보여요. 클릭하면 상세 페이지로 갈 수 있어요.

**③ 진행률 (오늘 처리 현황)**
> ```
> 출고:  완료 0   진행 1   대기 2
>        ━━━━━━━━━━━━━━━━━━━━━━ (진행률 0%)
> ```
> 마지막으로 **어디까지 진행됐는지** 봐요.

→ 사용자는 자연스럽게 흐름을 따라가요.
**"3건 있네"** → **"무엇 무엇이지"** → **"어디까지 됐지"** → **클릭해서 처리**.

---

## 4. 각 패널이 뭐 하는 곳인가

### 상단 KPI 카드 5개 — "오늘 상황 한 줄 요약"

각 카드는 큰 숫자 하나만 보여줍니다.

- **오늘 입고**: 오늘 처리해야 할 입고 건수 (오늘 마감 + 지연된 것)
- **오늘 출고**: 오늘 처리해야 할 출고 건수
- **재고 부족**: 안전재고 밑으로 떨어진 품번 수
- **미처리 지시서**: 모든 미완료 지시서 (입고+출고+이동 합쳐서)
- **승인 대기**: 결재가 필요한 초안(draft) 지시서 수

**핵심**: 카드 제목 아래에 "이 숫자가 뭘 의미하는지" 작은 글씨로 항상 적어요. 안 그러면 "오늘 입고가 뭐지? 오늘 들어올 거? 오늘 처리할 거?" 헷갈리니까요.

### 처리 필요 지시서 — "내가 행동해야 할 목록"

5개 탭으로 분류해서 보여줘요.

| 탭 | 무엇이 들어가나 |
|---|---|
| **전체** | 아래 4개 다 합친 목록 |
| **지연** | 마감일 지났는데 아직 미완료인 것 |
| **오늘마감** | 오늘이 마감인데 아직 미완료인 것 |
| **진행중** | 지금 작업 중인 것 (날짜 무관) |
| **승인대기** | 초안 상태로 결재가 필요한 것 |

**왜 이렇게 나눴나**: 행동이 다르기 때문이에요.
- 지연 → 빨리 처리해야 함
- 오늘마감 → 오늘 안에 끝내야 함
- 진행중 → 추적만 하면 됨
- 승인대기 → 결재만 하면 됨

미래 마감(예: 5일 뒤 마감)은 일부러 **빼요**. 아직 행동할 필요 없는 거니까 노이즈만 됩니다.

### 오늘 처리 현황 — "팀 전체가 어디까지 했나"

도메인 4개(입고/출고/이동/반품) 각각 **완료/진행/대기** 카운트를 막대 그래프로 보여줘요.

```
입고:  완료 5   진행 2   대기 3   ━━━━━━━━━━━━━ (50%)
출고:  완료 0   진행 1   대기 2   ━━━━ (0%)
이동:  완료 1   진행 0   대기 0   ━━━━━━━━━━━━━━━━━ (100%)
반품:  완료 0   진행 0   대기 0   ━━━━ (0%)
```

**처리 필요 지시서랑 어떻게 다르냐**:
- 처리 필요 지시서 = **리스트** (어떤 것들이 있나)
- 오늘 처리 현황 = **카운트** (얼마나 진척됐나)

같은 데이터를 보는 각도가 달라요. 처리 필요 지시서의 "진행중 1건 + 대기 2건" 이 곧 오늘 처리 현황의 "진행 1, 대기 2" 와 일치합니다.

### 창고 미니맵 — "어디서 일이 일어나나"

창고를 위에서 본 평면도예요. 구역(zone)별로 점유율이 색깔로 표시됩니다. 클릭하면 레이아웃 편집 화면으로 이동.

### 최근 7일 입·출고 추이 — "이번 주 흐름이 정상인가"

지난 7일 동안 매일 얼마나 들어오고 나갔는지 라인 차트. 어느 날 갑자기 튀거나 바닥이면 이상 신호로 알아챌 수 있어요.

### 오늘의 이슈 — "긴급 처리 안내판"

지금 즉시 누가 손대야 하는 일들이에요.

```
🚨 [긴급]  재고 부족 품번 181건
          → "긴급 발주" 버튼

⚠️ [주의]  승인 대기 3건
          → "승인 처리" 버튼
```

버튼 누르면 바로 해당 페이지로 이동.

### 재고 부족 품목 — "특별히 모자란 것 상위 N개"

안전재고 미달 SKU 8개를 부족 수량 순으로 나열. 자세한 건 `/common/low-stock` 페이지에서 확인.

### 최근 작업 로그 — "누가 뭘 했나"

감사 로그(audit log) 최근 8건 미리보기. 누가 언제 어떤 API를 호출했는지 봐요. 문제 생겼을 때 추적용.

## 5. 데이터는 어디서 오나

핵심 원칙 한 가지를 꼭 지켰어요.

> **"숫자 계산은 백엔드에서. 프론트는 받아서 그리기만."**

```
백엔드 (DashboardService)
   │
   │  COUNT(*) 쿼리 ~20개
   │  (각각 매우 가볍게 셈)
   ▼
DashboardSummaryDto (JSON 한 덩어리)
   │
   │  /stock-service/dashboard/summary
   ▼
프론트엔드 (useDashboardSummary)
   │
   ▼
각 패널은 이 summary에서 필요한 필드만 꺼내서 표시
```

**왜 이렇게 했나**:
- 프론트가 입고/출고/이동 전체 리스트를 다운로드해서 직접 카운트하면 → 데이터 많아지면 느려짐
- 백엔드 로직이 바뀌면 → 프론트도 같이 고쳐야 해서 깨지기 쉬움
- 한 곳에서만 계산 → 모든 패널이 같은 숫자를 봄 (정합성)

## 6. 색깔 규칙

전체 화면에서 색을 일관되게 써요. 색만 봐도 무엇인지 알 수 있게.

### 도메인별 색

| 도메인 | 색깔 |
|---|---|
| 입고 | 하늘색 |
| 출고 | 보라색 |
| 이동 | 초록색 |
| 반품 | 주황색 |

KPI 카드, 진행률 막대, 태그 모두 같은 색을 써요.

### 카테고리 색 (처리 필요 지시서)

| 카테고리 | 색깔 | 의미 |
|---|---|---|
| 지연 | 주황 | 빨리 처리해야 함 |
| 오늘마감 | 빨강 | 긴급 |
| 진행중 | 파랑 | 추적만 |
| 승인대기 | 노랑 | 결재 필요 |

색이 곧 메시지예요. 빨강이 보이면 즉시 손대야 한다는 뜻.

## 7. 새로운 패널을 추가할 때

대시보드에 새 위젯을 만들고 싶다? 이 5가지 질문을 먼저 해보세요.

**1. 어떤 단면인가?**
숫자 / 리스트 / 진행률 / 지도 / 경보 중 무엇이에요?

**2. 어디에 둘까?**
위에서 아래로 압축 → 디테일 흐름이에요. 너무 자세한 건 위에 두면 안 됩니다.

**3. 데이터는 백엔드 summary에 있나?**
없으면 **백엔드부터** 추가하세요. 프론트에서 직접 계산하지 마세요.

**4. 다른 패널과 정보가 겹치나?**
같은 사실을 다른 형태로 보여주는 건 OK (좋아요).
같은 형태로 또 보여주는 건 NO (지웁시다).

**5. 클릭하면 어디로 가나?**
대시보드의 모든 항목은 행동으로 이어져야 해요. 그냥 표시만 하는 카드는 가치가 떨어집니다.
